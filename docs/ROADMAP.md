# План развития

Дата обновления: **11.11.2026** (Asia/Tbilisi).

## Переход на многометочную классификацию

Дата постановки: **11.11.2026**. Статус: **в работе; чекпоинты 1–2 реализованы; чекпоинты 3–8 не завершены**.

Цель: одно объявление получает все подходящие категории. Однокатегорийная разметка остаётся допустимым частным случаем. Например, `electronics|home` означает две категории, а не отдельный составной класс. Архитектура SimpleNN сохраняется.

Чекпоинты ниже — последовательные условия готовности, а не календарные сроки. После завершения каждого этапа отметить пункты, записать фактическую дату и ссылку на результат проверки. Смена действующей модели допускается только после проверки обучения, прогноза и согласования интеграции с Telegram Finder.

### Исходные данные и ограничения на 11.11.2026

Все строки имеют `annotation_status=completed`, но это само по себе не отменяет флаги дополнительной проверки. Показатели относятся к предварительному снимку файла; перед обучением их нужно пересчитать. Числа причин исключения могут пересекаться, поэтому их нельзя просто складывать.

До выполнения чекпоинта 1 `utils/util.py` кодировал всю строку `label` через LabelEncoder, создавая самостоятельные классы для сочетаний категорий. После выполнения чекпоинта 1 загрузчик возвращает списки меток и отчёт допуска; `train.py` останавливается на многометочном наборе до записи модели. Функция потерь пока остаётся cross entropy, а пакетный прогноз и Flask выбирают один выход через argmax.

Повторная проверка актуального `labeled.csv` при реализации чекпоинта 1 (11.11.2026): прочитано и допущено **46 701** строка, из них **1 810** многометочных; исключений, включая `review`, не обнаружено. Это другой снимок данных по сравнению с предварительной таблицей выше. Исходный CSV при проверке не изменялся, что подтверждено совпадением SHA-256 до и после чтения.

Сохраняются обязательные ограничения проекта:

- Поддержка CSV и XLSX при обучении и пакетном прогнозе.
- SimpleNN: Linear → ReLU → Linear, скрытый слой из 100 нейронов.
- Согласованный комплект `model.pth`, `vectorizer.pkl`, `labels_encoded.json` из одного запуска.
- Сохранение связи идентификаторов сообщений с результатами `POST /predict`.
- Проверки на временных синтетических данных с временными `--model-dir` и `--output`.
- Пользовательский CSV, действующая модель и `.env` не изменяются; локальные данные и модели не добавляются в Git или Docker-образ.
