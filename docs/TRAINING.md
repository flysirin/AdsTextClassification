# Данные, обучение и перенос

После обучения multilabel-кандидата можно без переобучения подобрать пороги на validation и затем оценить независимый test: [команды и правила оценки](EVALUATION.md). Подбор не изменяет три файла кандидата.

CSV читается в UTF-8 с BOM или без него. Поддерживаются запятая и точка с запятой. Кавычки и переносы внутри поля обрабатываются как часть CSV. Результат в CSV записывается с BOM и разделителем «точка с запятой». Первая строка каждой таблицы содержит заголовки.

```csv
text;label
Продаю деревянный стол;home
Продаю ноутбук и холодильник;electronics|home
Ищу работу поваром;jobs
```

## Разметка и допуск строк

Правила подготовки реализованы 11.11.2026, в рамках первого чекпоинта [Roadmap](ROADMAP.md). Обязательные столбцы — `text` и `label`. Каждая строка должна содержать полный набор подходящих категорий: отсутствие категории считается отрицательной меткой. Гарантированно однокатегорийные данные переразмечать не требуется.

Категории разделяются вертикальной чертой `|`. Пробелы вокруг элементов и повторные категории удаляются, категории сортируются. Например, ` home | electronics | home ` превращается в `electronics|home` и список `["electronics", "home"]`. Текст объявления, включая пробелы, кавычки и переносы, сохраняется. Загрузчик `utils/training_data.py` возвращает подготовленную таблицу с дополнительной колонкой `labels`, содержащей списки, и отчёт. Служебная колонка `_source_record` содержит номер исходной записи с 1 без заголовка и сохраняет связь с исходником после фильтрации; имя зарезервировано загрузчиком. Исходный файл не изменяется. Для обучения списки преобразуются в multi-hot цели.

Допустимые категории, с учётом регистра:

```text
animals, children, clothing, electronics, food, health, hobby, home,
jobs, no_ads, other, real_estate, services, spam, transport
```

Названия соответствуют справочнику разметки; русские подписи и неизвестные коды автоматически не переименовываются. `other` — самостоятельная содержательная метка объявления вне основных тематик. `review` — служебное состояние неопределённости, оно исключает всю строку, даже в сочетании `review|home`. Пустая разметка не является примером без категорий и тоже исключается. Пустой список результата будущей модели — отдельный случай прогноза, а не метка `review` или `other`.

Для подготовки данных `no_ads` и `spam` используются только отдельно. Их сочетания с другими категориями, включая друг друга, исключаются как конфликт; загрузчик не выбирает победившую категорию и не исправляет смысл разметки. `other` допускается вместе с тематическими категориями. Маршрутизация специальных категорий и новый ответ API будут согласованы отдельно в чекпоинте 6.

Дополнительные поля контроля качества необязательны для обычных таблиц из двух столбцов. Если поле присутствует, оно проверяется для каждой строки:

| Поле | Условие допуска |
| --- | --- |
| `review_required` | Только `false`; допускаются логические значения Excel и строки `true`/`false` без учёта регистра и внешних пробелов. `true`, пустое или неизвестное значение исключают строку. Числа `0`/`1` не заменяют логический флаг |
| `annotation_status` | Только `completed`, без учёта регистра и внешних пробелов. Пустое значение, `pending`, `legacy_unverified` и неизвестные состояния исключают строку |
| `qa_status` | Пустое значение или `done`, без учёта регистра и внешних пробелов. `pending` и любые другие незавершённые/неизвестные состояния исключают строку |

Пустой статус QA допустим: повторная QA-проверка не является обязательным условием для всех строк. Проверки `annotation_status` и `review_required` при этом сохраняются. Наличие только `annotation_status=completed` не отменяет необходимость исключить `review` или незавершённый QA.

## Проверка данных без обучения

Из корня проекта в WSL:

```bash
uv run --locked --extra cpu python -m utils.training_data --input data/train_data/labeled.csv
```

Команда только читает таблицу и выводит JSON-отчёт: `total_rows`, `accepted_rows`, `excluded_rows`, `multilabel_rows` (среди допущенных), `exclusion_reasons` и `examples`. Последнее поле содержит до пяти номеров записей на причину, начиная с 1 без заголовка. Это не физические строки CSV и не `message_id`. Сумма причин может превышать число исключённых записей, поскольку у одной записи бывает несколько нарушений.

| Код причины | Значение |
| --- | --- |
| `empty_text` | Нет непустого текста |
| `empty_label` | Нет разметки |
| `empty_label_element` | Пустая категория: например, `home||electronics` или `home|` |
| `unknown_label` | Категория отсутствует в справочнике |
| `review_label` | Среди меток есть `review` |
| `exclusive_label_conflict` | `no_ads` или `spam` сочетается с другой меткой |
| `review_required` | Флаг дополнительной проверки равен `true` |
| `invalid_review_required` | Флаг присутствует, но пуст или имеет неизвестное значение |
| `annotation_incomplete` | Аннотация не подтверждена как `completed` |
| `qa_incomplete` | QA имеет непустое состояние, отличное от `done` |

Ошибочные строки исключаются из подготовленной таблицы с отражением причин в отчёте. Если нет обязательных столбцов, проверка завершается ошибкой. Если ни одна строка не допущена, команда сначала выводит отчёт, затем завершается с кодом 1. Нулевой код команды означает наличие допущенных строк, но не отсутствие исключений: проверяйте `excluded_rows` и причины.

## Группировка и разделение без утечки повторов

Второй чекпоинт реализует `utils/dataset_split.py`. После допуска строк записи объединяются в связные группы по любому из двух признаков: одинаковый непустой `message_id` или одинаковый нормализованный текст. Связь транзитивна: если две записи имеют общий ID, а третья повторяет текст второй, все три входят в одну группу. Пустые ID не связывают записи между собой; непустые сравниваются по строковому значению без внешних пробелов.

Нормализация `nfkc-casefold-whitespace-v1` выполняет Unicode NFKC, `casefold` и замену последовательностей пробельных символов одним пробелом с удалением внешних пробелов. Пунктуация, ссылки и содержание объявления сохраняются. Нормализованная форма используется только для сравнения, текст обучающего примера не переписывается.

Если внутри группы есть разные наборы меток, исключается вся группа. Списки меток не объединяются автоматически, семантическое решение за разметчика не принимается. В остальных группах оставляется первый пример каждого нормализованного текста; повторные экземпляры исключаются, чтобы не увеличивать их вес. При одном ID и разных текстах сохраняются все различные тексты с одинаковой разметкой, но всегда в одной части.

Разделение выполняется в пропорции **80% обучение / 10% валидация / 10% независимый тест**, по умолчанию с `seed=42`. Группы неделимы, поэтому размеры приблизительные. Сначала распределяются группы редких категорий, затем учитываются недостающая представленность меток и целевые размеры частей. Для каждой оставшейся категории сохраняется хотя бы одна группа в обучении. Категория с единственной группой попадает только в обучение. Алгоритм стремится представить метку во всех частях, но связанные многометочные группы могут препятствовать этому; ограничения явно отражаются в отчёте. Если нельзя получить три непустые части, подготовка завершается понятной ошибкой.

Для сохранения состава частей без обучения выполните из корня проекта в WSL:

```bash
uv run --locked --extra cpu python -m utils.dataset_split \
  --input data/train_data/labeled.csv \
  --output data/prepared/candidate-split \
  --seed 42
```

`--output` должен указывать на **новый каталог**. Существующий каталог или файл не перезаписывается. Создаются два локальных файла:

- `manifest.json`: версия формата, SHA-256 исходного файла, seed, пропорции, нормализация, номера исходных записей в каждой части, состав групп, конфликтующие наборы меток и соответствие удалённых повторов оставленным записям. Тексты объявлений не копируются. Манифест позволяет восстановить состав частей по номерам записей в исходном файле с совпадающим SHA-256.
- `report.json`: отчёт первичного допуска, количество конфликтов и повторов, размеры частей, число положительных примеров и независимых групп каждой категории, попарные пересечения групп, текстов и ID. `missing_categories` перечисляет отсутствующие категории по частям, `low_evaluation_support` — категории с менее чем 10 примерами в валидации или тесте. Порог 10 служит диагностическим сигналом, а не гарантией статистической надёжности.

Если файл изменился во время подготовки, результат не сохраняется. Для воспроизведения нужны тот же исходный файл, seed и версия реализации; состав проверяется по манифесту. Эти локальные JSON исключены действующими правилами Git и Docker; они относятся к подготовке выборки и не меняют контракт трёх файлов модели.

Проверка 11.11.2026 сохранена в `data/prepared/multilabel-2026-11-11/`: из 46 701 допущенной строки исключена 31 строка в 14 конфликтующих группах и 2 015 повторов. Осталось 44 655 примеров: 35 721 / 4 468 / 4 466. Все 15 категорий присутствуют в каждой части; пересечения по всем трём признакам нулевые. Повторное вычисление с тем же seed дало тот же манифест; исходный CSV не изменился.

## Multilabel-обучение

С 11.11.2026 третий чекпоинт реализован в `utils/training.py` и доступен через флаг `--multilabel`. Одиночные и совместные метки обучаются вместе. Архитектура SimpleNN сохранена: Linear → ReLU → Linear, скрытый слой из 100 нейронов, на выходе логиты.

### Интерактивный запуск

Для выбора параметров на NVIDIA выполните без аргументов:

```bash
bash scripts/train_cuda.sh
```

Мастер `scripts/train_interactive.py` использует существующие настройки `config/config.py`. Таблицы читаются из `TRAIN_DATA_PATH`, базовое имя и место нового кандидата определяются по `MODEL_PATH`. Относительные значения настроек считаются от корня проекта, абсолютные используются напрямую. Пути в мастере не дублируют строки `data/train_data` и `saved/model`.

| Вопрос | Предлагаемое значение |
| --- | --- |
| Режим | `1` — multilabel; `2` — singlelabel |
| Способ для multilabel | `1` — новый, лучшие веса и ранняя остановка; `2` — старый, все эпохи |
| Таблица | `labeled.csv`, если есть; иначе первая CSV/XLSX в отсортированном списке |
| Максимальное количество эпох | `100` |
| Каталог сохранения | Новый каталог рядом с `MODEL_PATH`, с именем на основе рабочего каталога, режима и времени |

Enter принимает значение в квадратных скобках. Например, при `MODEL_PATH=saved/model` мастер предложит `saved/model-multilabel-20261111-153000`. Время имени формируется в часовом поясе Asia/Tbilisi. Если предложенное имя занято, подбирается свободное с числовым суффиксом.

Если ввести только имя, например `my-model`, оно создастся рядом с настроенным `MODEL_PATH`. Относительный путь с несколькими компонентами считается от корня проекта, абсолютный путь используется напрямую. Существующий путь, рабочий каталог модели и его вложенные каталоги отклоняются в обоих режимах; мастер повторит вопрос. Ошибочные номера и неположительное число эпох тоже можно исправить повторным вводом. Временные файлы Excel с префиксом `~$` в список таблиц не включаются.

После выбора отображается сводка и начинается обучение. Закрытие ввода или Ctrl+C во время диалога отменяет запуск. В выбранном каталоге сохраняется комплект из `model.pth`, `vectorizer.pkl` и `labels_encoded.json`.

Для такого же диалога в CPU-профиле:

```bash
uv run --locked --extra cpu python -m scripts.train_interactive --device cpu
```

### Запуск с параметрами

Для обучения кандидата на CPU:

```bash
uv run --locked --extra cpu python train.py \
  --input data/train_data/labeled.csv \
  --multilabel \
  --epochs 100 \
  --batch-size 128 \
  --seed 42 \
  --model-dir saved/candidate-multilabel
```

Для multilabel обязателен явный `--model-dir` с **новым каталогом** вне `saved/model/`. Существующие файлы и каталоги кандидатов не перезаписываются. Рабочий каталог модели и его вложенные каталоги отклоняются до обучения. Для повторного запуска укажите другое имя кандидата.

После группового разделения 80/10/10 MultiLabelBinarizer получает явно заданный алфавитный порядок категорий из обучающей части. Если категория валидации или теста отсутствует в обучении, запуск завершается ошибкой. Каждый выход модели должен иметь положительные обучающие примеры. Составные классы вида `electronics|home` не создаются. При порядке `electronics, home` цели для `home` и `electronics|home` равны `[0, 1]` и `[1, 1]`.

Цели имеют тип float32 и форму `[размер_пакета, число_категорий]`. BCEWithLogitsLoss принимает логиты напрямую; отдельного sigmoid перед функцией потерь нет. Обучение идёт пакетами с Adam и learning rate 0.001. По умолчанию `--epochs=100`, `--batch-size=128`, `--seed=42`. Число эпох и размер пакета должны быть положительными, seed — целым от 0 до `2**32 - 1`. Нечисловые потери приводят к остановке без сохранения модели. CountVectorizer обучается только на обучающей части.

По умолчанию веса категорий не применяются. Необязательный `--pos-weight` вычисляет для каждой категории отношение числа отрицательных примеров к положительным **только в train**. Если категория присутствует в каждой обучающей строке, используется вес 1 вместо 0, чтобы сохранить сигнал обучения. Веса не подбираются по валидации и не используют тест; сравнение качества вариантов относится к следующему этапу.

В консоль выводится средняя потеря каждой эпохи и итоговый BCE на валидации без весов. Пороги не подбираются, категории для рабочего прогноза пока не выбираются. Независимая тестовая часть в multilabel-режиме не векторизуется и не используется для оценки модели; её метки проверяются только на наличие обученных категорий. Подбор порогов и окончательная оценка качества относятся к чекпоинту 4 [Roadmap](ROADMAP.md).

Seed задаёт разделение, начальные веса и порядок пакетов. Включены детерминированные алгоритмы PyTorch; для CUDA задаётся `CUBLAS_WORKSPACE_CONFIG=:4096:8`, если переменная ещё не установлена. Повторяемость проверяется в одном окружении и на одном устройстве; побитовое совпадение между CPU, разными GPU и версиями библиотек не предполагается.

## Артефакты кандидата и совместимость

Сохраняются только три обязательных файла с прежними структурами:

- `model.pth` — обычный state_dict с ключами `fc1` и `fc2`, веса на CPU для переноса.
- `vectorizer.pkl` — обученный CountVectorizer с тем же словарём признаков.
- `labels_encoded.json` — прежний плоский JSON `индекс выхода → название категории`.

В объект CountVectorizer добавлены необязательные атрибуты: `classification_task_` со значением `multilabel` или `singlelabel`, `training_config_` и `training_history_`. Они не требуют нового класса векторизатора или четвёртого файла. Конфигурация сохраняет seed, эпохи, размер пакета, устройство, функцию потерь, optimizer, learning rate, порядок категорий, применённые веса, версию PyTorch, SHA-256 исходника и номера записей всех частей. История содержит потери эпох и валидационный BCE.

Текущие Flask API и пакетный прогноз поддерживают прежнюю выдачу одной категории. Они отклоняют помеченный multilabel-кандидат вместо применения argmax: API сообщает `model_ready=false` и `model_load_failed`, прогноз возвращает 503; пакетная команда завершается до записи результата. Старый CountVectorizer без атрибута режима остаётся совместимым и считается singlelabel. Новый формат выдачи, хранение порогов и перенос в Telegram Finder требуют чекпоинтов 4–6. Multilabel-кандидат пока не подключайте к рабочему Finder или прежнему загрузчику, который не проверяет режим.

## Прежний режим обучения и прогноз

Без `--multilabel` сохраняется однокатегорийное обучение с CrossEntropyLoss и совместимая выдача API. Передавать несколько категорий в этом режиме нельзя: команда подскажет добавить `--multilabel` и новый каталог кандидата. `--pos-weight` допустим только с `--multilabel`. `review` и незавершённые проверки исключаются в обоих режимах.

Однокатегорийный режим использует то же групповое разделение 80/10/10 и пакетное обучение. Порядок выходов задаётся MultiLabelBinarizer по train; цели для CrossEntropyLoss преобразуются в индексы одиночных меток. В конце выводятся accuracy и взвешенные precision, recall, F1 на независимых тестовых 10%. При прогнозе сохраняются исходные строки, колонки `predicted_label` и `label` содержат индекс и название одной категории.

Для обучения на NVIDIA в WSL запустите Bash-скрипт из корня проекта.

```bash
bash scripts/train_cuda.sh --input data/train_data/ads.xlsx --epochs 100 --model-dir saved/candidate
```

Для multilabel на GPU:

```bash
bash scripts/train_cuda.sh --multilabel \
  --input data/train_data/labeled.csv \
  --epochs 100 --batch-size 128 --seed 42 \
  --model-dir saved/candidate-multilabel-gpu
```

Скрипт использует CUDA-профиль из uv.lock и устройство cuda. При первом запуске uv установит зависимости в .venv-cuda. Если задан UV_PROJECT_ENVIRONMENT, uv использует этот путь. Без аргументов скрипт запускает полный мастер выбора параметров. При наличии аргументов он передаёт их прямо в `train.py`; если среди них отсутствует `--input`, остаётся прежний выбор только таблицы. Относительные пути считаются от корня проекта. При недоступном GPU train.py завершится с сообщением до чтения таблицы.

Однокатегорийный кандидат проверьте через пакетный прогноз с `--model-dir` и API с `MODEL_PATH`. После проверки перенесите все три файла из одного запуска в отдельный каталог релиза на сервере, подключите его к контейнеру и проверьте `/health`. Multilabel-кандидат до завершения новых порогов и контракта API проверяется только как результат обучения. Для отката сохраняйте предыдущий релиз. Загружайте `vectorizer.pkl` только из доверенного источника. Старый векторизатор из scikit-learn 1.5.1 требует проверки в новом окружении, при несовместимости переобучите комплект из исходной таблицы.
## Выбор способа обучения

Добавлено 11.11.2026. Способ обучения выбирается отдельно от режима категорий.
В мастере `bash scripts/train_cuda.sh` после выбора multilabel доступны:

- **Новый (по умолчанию в мастере):** проверка validation после каждой эпохи, сохранение лучших весов и ранняя остановка.
- **Старый:** все указанные эпохи, сохранение последних весов и проверка validation в конце.

Команды с аргументами сохраняют прежнее поведение: без `--training-mode` используется `legacy`.
Новый способ пока доступен только для multilabel; singlelabel работает прежним способом.

```bash
bash scripts/train_cuda.sh --multilabel --input data/train_data/labeled.csv --epochs 100 --model-dir saved/new-best --training-mode best --patience 5 --min-delta 0.0001
bash scripts/train_cuda.sh --multilabel --input data/train_data/labeled.csv --epochs 100 --model-dir saved/new-legacy --training-mode legacy
```

В `best` число эпох является максимумом. После каждой эпохи считаются train loss и validation BCE без весов категорий, даже при `--pos-weight`. Validation векторизуется один раз словарём из train и не обновляет модель. Независимый test не используется.

Любое строгое снижение validation BCE сохраняет независимую копию лучших весов. Счётчик ожидания сбрасывается, когда снижение относительно последнего существенного улучшения **строго больше** `min_delta`. Равенство не считается улучшением. По умолчанию после 5 последовательных эпох без такого улучшения обучение останавливается. `--no-early-stopping` выполняет весь максимум эпох, но в режиме `best` всё равно сохраняет лучшие веса. При достижении максимума лучшие веса также восстанавливаются.

Значения 100 эпох, patience 5 и min_delta 0.0001 являются начальными настройками, а не результатом подбора на реальных данных. Терминал показывает лучшую эпоху, выполненное число эпох и причину завершения (`patience` или `max_epochs`). В `vectorizer.pkl` сохраняются параметры в `training_config_`, история `losses` и `validation_losses`, `epochs_completed`, `best_epoch` (с 1), `best_validation_bce`, `validation_bce` сохранённых весов и `stop_reason` в `training_history_`. Для legacy история валидации по эпохам пуста, лучшая эпоха не выбирается.

Комплект остаётся прежним: `model.pth`, `vectorizer.pkl`, `labels_encoded.json`. Изменения действуют только при новом запуске. Уже работающий процесс продолжает обучение по загруженному коду.
