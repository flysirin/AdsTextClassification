Полный прогон выполняет пользователь вручную из корня проекта в WSL. Агент запускает весь набор только по прямой просьбе пользователя:

```bash
uv sync --locked --extra cpu
uv run --locked --extra cpu python -m pytest -q Tests
```

После изменения поведения агент выбирает только затронутый файл или отдельный тест, например:

```bash
uv run --locked --extra cpu python -m pytest -q Tests/test_train_interactive.py
uv run --locked --extra cpu python -m pytest -q Tests/test_training_data.py::test_two_column_input_needs_no_qa_fields
```

Все тестовые сценарии хранятся в `Tests/`. Не выполняйте отдельные пробные запуски, разовые проверки через `python -c` и временные тестовые скрипты вне этой папки. Дополнительный необходимый сценарий сначала оформляется в `Tests/` и описывается здесь. Вызовы обучения, API и прогноза внутри существующих тестов являются частью этих сценариев. Для изменений только документации, комментариев или форматирования тесты не запускаются.

Перед каждым тестом и самостоятельным блоком проверок внутри большого теста пишется короткий русский комментарий с назначением проверки.

Тесты создают таблицы и модели во временном каталоге. Сквозная проверка обучает модель одну эпоху, загружает комплект в Flask, запускает пакетный прогноз в XLSX и CSV и сравнивает результаты. Проверяются обе разновидности разделителя CSV, многострочный текст с кавычками и поведение API без модели. Эти проверки подтверждают совместимость компонентов. Качество реальной классификации оценивайте на размеченной контрольной выборке.

`Tests/test_training_data.py` проверяет первый чекпоинт multilabel: одинаковую подготовку CSV/XLSX, списки категорий и нормализацию повторных меток, исключение `review`, неизвестных категорий, конфликтов `no_ads`/`spam`, пустых полей и незавершённых проверок. Проверяется отчёт, неизменность исходного файла и отказ `train.py` от многометочного набора без явного флага `--multilabel`. Сквозной тест дополнительно подтверждает, что `review` отсутствует в словаре выходов сохранённой модели.

`Tests/test_dataset_split.py` проверяет второй чекпоинт: нормализацию Unicode, транзитивную группировку по ID и тексту, исключение всей конфликтующей группы, удаление повторов, отсутствие пересечений и воспроизводимость при фиксированном seed. Проверяется размещение единственного редкого примера в обучении и явное предупреждение об отсутствии этой категории в контрольных частях. Для CSV и XLSX проверяются номера исходных записей после фильтрации, сохранение манифеста и отчёта без текстов, неизменность исходника и отказ от перезаписи существующего каталога. Наборы с менее чем тремя независимыми группами отклоняются. Сквозной тест использует разные тексты и проверяет сохранённый словарь CountVectorizer: слова только из валидации и теста в него не попадают.

`Tests/test_multilabel_training.py` проверяет третий чекпоинт: float32 multi-hot цели, устойчивый порядок выходов, ошибку для категории только в контрольной части, веса из train и ненулевой сигнал для категории во всех строках. На синтетических примерах модель обучается выдавать две метки одновременно; проверяются конечные потери и одинаковые веса повторных запусков с тем же seed. После сохранения и загрузки сравниваются логиты, прежние четыре ключа state_dict, плоский JSON и параметры во векторизаторе. Команда обучения проверяется для CSV с обоими разделителями и XLSX, включая вариант с `--pos-weight`. Отдельно проверяются новый каталог кандидата, запрет записи в рабочую модель, совместимость старого векторизатора без метаданных и отказ текущих API/пакетного прогноза от multilabel вместо argmax. Все таблицы, кандидаты и защищаемые файлы в этих тестах временные.

CUDA-тест пропускается в CPU-профиле. Для проверки доступной NVIDIA в отдельном окружении из корня WSL выполните:

```bash
UV_PROJECT_ENVIRONMENT=.venv-cuda uv run --locked --extra cuda \
  python -m pytest -q Tests/test_multilabel_training.py -k cuda_smoke
```

Тест запускает `scripts/train_cuda.sh` на одну эпоху с временными таблицей и `--model-dir`, проверяет конечные потери и сохранение весов на CPU. Эти проверки подтверждают обучение и загрузку кандидата; качество реальной классификации, выбор порогов и новый контракт выдачи остаются следующими этапами.

Результат 11.11.2026: полный CPU-прогон — **33 passed, 1 skipped**; отдельный CUDA-тест — **1 passed, 11 deselected** на RTX 2060 с драйвером 617.42 и PyTorch 2.15.0+cu132. Пропуск в CPU-прогоне относится только к GPU-тесту, который затем прошёл в отдельном CUDA-окружении.

`Tests/test_train_interactive.py` проверяет мастер запуска: чтение каталогов из конфигурации, выбор `labeled.csv`, значения по Enter, повторный ввод при ошибках, исключение файлов блокировки Excel, пути с пробелами, подбор свободного имени и защиту рабочего каталога модели. Отдельная проверка запускает из диалога одну эпоху multilabel на временной CSV через настоящий `train.py`, сверяет режим и параметры сохранённого комплекта и неизменность исходной таблицы. Отмена ввода и отсутствие таблиц не запускают обучение.

Последний прогон до введения ограничения на автоматический полный запуск (11.11.2026), включая мастер: **39 passed, 1 skipped** на CPU; отдельный GPU-сценарий — **1 passed, 11 deselected**. После добавления комментариев и инструкции повторный прогон не выполнялся.
